# @workspace/api-zod

Zod validation schemas generated from the OpenAPI spec via [Orval](https://orval.dev/).

## What gets generated

Running codegen (`pnpm --filter @workspace/api-spec run codegen`) writes the
following files under `src/generated/` (the directory is wiped first because
`clean: true` is set in `orval.config.ts`):

```
src/generated/
  index.ts          ← barrel generated by orval (do NOT import this — see below)
  api/
    api.ts          ← the only real output: all Zod schemas live here
```

### Why `src/index.ts` imports the concrete file, not the barrel

Orval's zod generator with `mode: "split"` creates `index.ts` re-exporting
both `./api/api` **and** `./api/api.schemas`.  The `.schemas` sibling is
**never emitted** by the zod client — it is a react-query artefact that crept
into the barrel template.  Because `clean: true` wipes `generated/` on every
run, importing the barrel would immediately break the build.

`src/index.ts` therefore imports `./generated/api/api` directly and must
continue to do so.  If orval changes its output structure (e.g. adds new
files), update `src/index.ts` to match the **actual** files on disk, and
update this README.

## Adding or updating schemas

1. Edit `lib/api-spec/openapi.yaml`.
2. Run codegen: `pnpm --filter @workspace/api-spec run codegen`
3. The script automatically verifies that every path exported from
   `src/index.ts` exists on disk (see `scripts/src/validate-api-zod-index.ts`).
   If an export is stale the command exits non-zero before `typecheck:libs`.

## Valid exports

| Re-export path (in `src/index.ts`) | Actual generated file |
|-------------------------------------|-----------------------|
| `./generated/api/api`               | `src/generated/api/api.ts` |
